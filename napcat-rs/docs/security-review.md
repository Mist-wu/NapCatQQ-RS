# NapCatQQ-RS 安全审计

## 1. 审计范围

本次安全审计聚焦于 `config` 与 `plugin` 核心模块，关注以下攻击面：

- 配置文件路径注入
- 插件二进制/模块路径可达性与类型校验
- 插件 HTTP 端点 URL 与超时参数
- 插件执行/请求行为的输入校验缺失

## 2. 风险项与修复

### 2.1 配置文件路径未校验

- 风险：`NAPCAT_CONFIG_PATH` 可被注入任意路径，若路径不存在将直接报错，且未限定文件类型，间接扩大潜在错误面。
- 处理：
  - 新增 `validate_config_path`：通过 `fs::canonicalize` 标准化路径。
  - 要求目标必须为普通文件（非目录）。
  - `load_file` 统一使用校验后的路径读取文件。
  - 更新 `load_env` 测试中的环境变量设置方式，去除不再需要的 `unsafe` 调用。
- 结果：输入面收敛，减少奇异路径导致的异常行为。

### 2.2 Rust 插件可执行文件校验不足

- 风险：Rust 插件可加载任意路径文件，存在执行不受控二进制的风险。
- 处理：
  - 新增 `validate_plugin_path`（路径标准化 + 元数据校验 + 文件类型校验）。
  - Rust 插件分支进行执行权限检查（Unix 平台）。
  - 通过 `backend_from_definition` 将标准化后的可执行路径注入运行时。
- 结果：降低任意路径注入或目录路径执行风险。

### 2.3 WASM 插件模块类型校验不足

- 风险：加载未受控/错误类型模块会触发运行异常，增强攻击链。
- 处理：
  - 在 `WasmPlugin::validate_path` 中要求路径存在且扩展名为 `.wasm`。
  - 统一采用标准化路径后再创建运行对象。
- 结果：模块类型约束更明确，加载时失败更快可控。

### 2.4 HTTP 插件端点与超时缺少白名单约束

- 风险：HTTP 插件可传入非预期协议（如 `file://`）或极端超时值，放大拒绝服务或流量绕过风险。
- 处理：
  - 新增 `validate_http_endpoint`，仅允许 `http`/`https`。
  - 限制插件超时范围 `10..=60000` 毫秒。
  - HTTP 请求改用 `Url` 拼接，避免手工拼接字符串。
- 结果：攻击面收敛，减少协议级误用与超时失控。

## 3. 未完全覆盖项

- 插件来源签名/权限签发与动态加载白名单（签名校验、沙箱策略）尚未引入；下一阶段建议加入基于可信目录或签名的策略。
- `plugin` 的 `args` 参数仍允许任意参数，建议在 CLI/业务层进一步做参数白名单。
